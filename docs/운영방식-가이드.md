# 강의 운영 방식 가이드 (종합)

이 강의는 **상황에 따라 3가지 방식**으로 운영할 수 있습니다. 목적에 맞게 고르거나, 단계적으로 조합하세요.

## 한눈에 비교
| | **B안 — 셀프 PR** | **A안 — Fork 분담** | **C안 — GitHub Classroom** |
|---|---|---|---|
| 대상 | 개인 자습 / 입문 | 소~다수, 진짜 협업 | 정규 수업, 다수 + 자동화 |
| 레포 구조 | 내 레포 1개 | 강사 upstream + 학생 fork | 학생별 레포 자동 생성 |
| 리뷰어 | 본인(+강사 개입) | 강사 / 상호 리뷰 | 본인 + CI 자동 채점 |
| 충돌 해결 학습 | ❌ | ✅ | △ |
| 채점/진도 관리 | 수동 | 수동(PR 목록) | **자동(대시보드)** |
| 셋업 난이도 | ★ (가장 쉬움) | ★★ | ★★★ |
| 문서 | [structure-B-self-PR](structure-B-self-PR.md) | [structure-A-fork-분담](structure-A-fork-분담.md) · [기본](structure-A-fork-PR.md) | [structure-C-github-classroom](structure-C-github-classroom.md) |

## 선택 플로차트
```
개인 자습인가?
 ├─ 예 → B안 (셀프 PR)
 └─ 아니오(학생 다수)
       ├─ 자동 채점/진도 관리가 중요? → C안 (GitHub Classroom)
       └─ "같은 코드 협업 + 충돌 해결"이 목표? → A안 (Fork 분담)
```

## 추천 조합 (단계적)
1. **입문** — B안으로 PR 메커니즘 체득 (브랜치→PR→머지 한 바퀴)
2. **협업** — A안 Fork 분담으로 실제 cross-repo PR + 리뷰 왕복 + 충돌 해결
3. **운영** — 인원이 많아지면 C안 Classroom으로 자동화(채점·진도)

## 세 방식 공통 — 반드시 챙길 것
- **반복 리듬**: 실패 테스트(red) → 수정(green) → PR. 모든 방식에서 동일.
- **PR 4칸 템플릿**: What / Why / How / 테스트 ([PULL_REQUEST_TEMPLATE](../.github/PULL_REQUEST_TEMPLATE.md))
- **Squash merge**: `main`은 "버그 1개 = 커밋 1개", 왕복 과정은 PR 안에 보존
- **리뷰 후속**: 새 PR 금지 — 같은 브랜치에 커밋 추가 → PR 자동 갱신
- **CI**: PR마다 `dotnet test` 자동 실행 (A·C안에서 특히 중요)
