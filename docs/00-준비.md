# 0차시 — 준비와 멘탈 모델

## ❓ Q. PR은 왜 쓰나? 그냥 `main`에 바로 커밋하면 안 되나?
**A.** 됩니다. 하지만 PR은 세 가지를 공짜로 줍니다.
1. **격리** — 작업 중인 코드가 `main`(동작하는 코드)을 망가뜨리지 않음
2. **리뷰 지점** — 머지 전에 diff를 보고 "이게 맞나?" 멈춰 생각할 자리
3. **히스토리** — "이 버그를 왜 이렇게 고쳤지?"의 답이 PR에 영구 기록됨

이 강의의 핵심 주장: **PR은 코드 전달 수단이자 소통 수단이다.**

## 준비물
- .NET SDK (이 레포는 `net10.0`) — `dotnet --version`
- Git — `git --version`
- GitHub 계정 1개 (B안), 그룹이면 추가 계정/조직 (A안)

## 멘탈 모델 — 한 바퀴
```
main (항상 동작) ──●───────────────●──  ← 머지로만 들어옴
                    \             /
         feature/... ●──커밋──커밋●   ← 여기서 작업, PR로 제안
```

## 확인
```bash
dotnet test   # "통과! 실패: 0, 통과: 2" 가 보이면 준비 완료
```
