# 1차시 — 첫 PR 왕복 (메커니즘)

> 목표: **내용이 아니라 "한 바퀴"를 손에 익히는 것.** 브랜치 → 커밋 → push → PR → diff → 머지 → 브랜치 삭제.

## ❓ Q. "PR을 한 바퀴 돈다"는 게 뭔가?
**A.** main이 아닌 브랜치에서 변경을 만들고, 그 변경을 main에 **합쳐달라고 제안(PR)** 한 뒤, 확인하고 **머지**하는 왕복입니다. 이번엔 README에 한 줄 추가하는 사소한 변경으로 연습합니다.

## 실습 (B안 기준 — 본인 레포)
```bash
# 1) 작업 브랜치 생성
git switch -c feature/add-greeting

# 2) 아무 사소한 변경 — 예: README 맨 아래 한 줄 추가
#    (에디터로 "## 수강 노트" 섹션 한 줄 추가)

# 3) 커밋
git add README.md
git commit -m "docs: 수강 노트 섹션 추가"

# 4) 원격으로 push
git push -u origin feature/add-greeting

# 5) GitHub에서 PR 열기 (base: main  ←  compare: feature/add-greeting)
#    제목: "docs: 수강 노트 섹션 추가"
#    본문: 왜 추가했는지 1~2줄

# 6) "Files changed" 탭에서 diff 를 눈으로 확인

# 7) Merge → 로컬 정리
git switch main
git pull
git branch -d feature/add-greeting
```

## ❓ Q. 변경을 다 하고 나서야 PR을 여나?
**A.** 아니어도 됩니다. **Draft PR**로 일찍 열어두고 커밋을 쌓아가는 방식도 흔합니다. 이번엔 완성 후 열어 흐름부터 익힙니다.

## 체크리스트
- [ ] 브랜치 이름이 `feature/...` 형태인가
- [ ] 커밋 메시지가 "무엇을 했는지" 한 줄로 설명되는가
- [ ] PR diff에 의도한 변경만 담겼는가 (불필요한 파일 섞이지 않음)
- [ ] 머지 후 feature 브랜치를 삭제했는가
