# 과제 자동 생성기 설계안 (N명 분담 샘플)

> **목적**: "학생 수 N"을 입력하면, [Fork 분담 방식](structure-A-fork-분담.md)에 맞는 **분담 과제 샘플(계산기 등)** 이 결정적으로 생성되도록 하는 명세.
>
> **사용법 (자연어 명령)**: 이 문서와 함께 아래처럼 지시하면 생성됩니다.
> - `"7명에서 분담하여 만드는 계산기 샘플 만들어줘"`
> - `"학생 12명, 날짜 유틸 과제로 생성해줘"`
> - `"5명, 계산기, 난이도 쉬움 위주로"`

---

## 1. 입력 파라미터

| 파라미터 | 필수 | 기본값 | 설명 |
|---|---|---|---|
| `N` (학생 수) | ✅ | — | 분담할 학생 수. 명령에서 "7명" 등으로 지정 |
| `project` | — | `계산기` | `계산기` \| `날짜유틸` \| `문자열파서` (버그 뱅크가 있는 도메인) |
| `language` | — | `C# (net10.0)` | 프로젝트 언어/런타임 |
| `difficulty` | — | `혼합` | `쉬움` \| `보통` \| `어려움` \| `혼합` — 버그 선택 가중치 |
| `mode` | — | `분담` | `분담`(1인 1버그) \| `경쟁`(여러 명이 같은 버그) |

명령에서 언급 안 된 값은 기본값 사용.

---

## 2. 버그 뱅크 (계산기 — 재사용 엣지 케이스 풀)

생성기는 이 풀에서 `N`개를 골라 배정한다. (N이 풀 크기보다 크면 §4 경쟁 모드)

| id | 엣지 케이스 | 대상 메서드 | 난이도 | 브랜치명 |
|---|---|---|---|---|
| B01 | 0으로 나누기 (DivideByZeroException) | `Divide` | 쉬움 | `fix/divide-by-zero` |
| B02 | 음수 입력 미검증 | `Sqrt` | 쉬움 | `fix/negative-sqrt` |
| B03 | int 오버플로 (곱셈) | `Multiply` | 보통 | `fix/multiply-overflow` |
| B04 | 반올림 정밀도(소수점 둘째 자리) | `Round2` | 보통 | `fix/rounding-precision` |
| B05 | 모듈로 음수 결과 부호 | `Mod` | 보통 | `fix/negative-modulo` |
| B06 | 0의 0제곱 (0^0) 정의 | `Power` | 어려움 | `fix/zero-pow-zero` |
| B07 | 로그 0/음수 입력 | `Log` | 보통 | `fix/log-domain` |
| B08 | 퍼센트 계산 경계(base 0) | `Percent` | 쉬움 | `fix/percent-zero-base` |
| B09 | 문자열→숫자 파싱 실패 처리 | `Parse` | 보통 | `fix/parse-invalid` |
| B10 | 큰 수 합산 int→long 승격 | `Sum` | 보통 | `fix/sum-overflow` |
| B11 | 아주 작은 수 비교(부동소수 == ) | `AreEqual` | 어려움 | `fix/float-equality` |
| B12 | 평균 — 빈 배열 | `Average` | 쉬움 | `fix/average-empty` |
| B13 | 할인율 범위(0~1 벗어남) | `ApplyDiscount` | 쉬움 | `fix/discount-range` |
| B14 | 세금 계산 반올림 누적 오차 | `AddTax` | 어려움 | `fix/tax-rounding` |
| B15 | 음수 금액 입력 가드 | `Charge` | 쉬움 | `fix/negative-amount` |

> 각 버그 엔트리는 생성 시 **(① 버그 심긴 메서드 구현, ② 실패하는 테스트, ③ 수정 힌트)** 를 함께 만든다. 세부 스펙은 §6 참고.
>
> 다른 도메인(`날짜유틸`, `문자열파서`)은 같은 형식의 별도 버그 뱅크를 둔다(부록 A).

---

## 3. 분담 알고리즘 (N → 배정)

1. `difficulty`에 따라 풀을 정렬/가중:
   - `혼합` → 쉬움/보통/어려움을 **라운드로빈**으로 섞어 난이도 균형
   - 특정 난이도 지정 → 해당 난이도 우선, 부족분은 인접 난이도에서 채움
2. 앞에서 `min(N, 풀크기)` 개를 선택.
3. `학생01 … 학생NN` 에 순서대로 1:1 배정.
4. 각 학생에게 **버그 id + 브랜치명** 고정.
5. `N > 풀크기` → §4 경쟁 모드.

> 결정적(deterministic): 같은 입력이면 항상 같은 배정. (풀 순서 고정)

---

## 4. 경쟁 모드 (학생 수 > 버그 수)

- 남는 학생은 **기존 버그에 중복 배정**하되, 브랜치명에 접미사: `fix/divide-by-zero` → `fix/divide-by-zero-2`.
- 같은 버그를 받은 학생들은 각자 fork에서 풀고, 강사가 **베스트 PR 1개 채택 + 나머지 Close(+코멘트)**.
- 탈락 학생도 자기 PR과 채택 PR을 비교 열람 가능 (upstream 접근 권한 전제).

## 5. 생성 산출물 (폴더 구성)

```
<sample-root>/
├─ Calculator.slnx
├─ README.md                      # 과제 개요 + N명 분담표
├─ src/Calculator/
│   └─ Calculator.cs              # 선택된 N개 버그가 시드된 구현
├─ tests/Calculator.Tests/
│   └─ CalculatorTests.cs         # happy-path(green) + N개 실패 테스트(주석/Skip)
├─ docs/
│   ├─ 분담표.md                   # 학생 ↔ 버그 ↔ 브랜치 매핑
│   └─ assignments/               # ◀ "학생 수만큼 폴더/카드 구성"
│       ├─ student-01.md          # 학생01 과제 카드 (버그 설명·재현·목표·체크리스트)
│       ├─ student-02.md
│       └─ ... student-NN.md
├─ .github/
│   ├─ PULL_REQUEST_TEMPLATE.md
│   └─ workflows/ci.yml           # PR마다 dotnet test
└─ (선택) GitHub Issues           # 버그 1개당 이슈 1개 (gh로 생성)
```

- **`docs/assignments/student-NN.md`** 가 "학생 수 입력 → 폴더(카드) 구성"의 실체.
- 각 카드에는 그 학생의 버그만 설명 → 학생은 자기 카드만 보고 작업.

### 학생 과제 카드 템플릿 (`student-NN.md`)
```markdown
# 학생NN 과제 — {버그 제목}

## 담당 엣지 케이스
- id: {Bxx}
- 대상 메서드: `Calculator.{메서드}`
- 브랜치: `{브랜치명}`

## 문제 (재현)
{버그 입력 → 잘못된 결과/예외}

## 목표
1. 실패하는 테스트를 재현/추가한다 (red)
2. `Calculator.{메서드}` 를 고친다 (green)
3. PR을 연다 (base = upstream:main ← compare = 내fork:{브랜치명})

## 체크리스트
- [ ] 실패 테스트 추가 커밋 (test:)
- [ ] 수정 커밋 (fix:)
- [ ] `dotnet test` 전체 통과
- [ ] PR 4칸 템플릿 작성
```

## 6. 생성 절차 (어시스턴트가 따르는 단계)

명령을 받으면 아래 순서로 수행한다.

1. **파라미터 파싱**: 명령에서 `N`, `project`, `difficulty`, `mode` 추출. 없으면 기본값.
2. **버그 선택**: §3 알고리즘으로 `N`개(또는 경쟁 배정) 결정.
3. **프로젝트 스캐폴드**:
   - `dotnet new sln` / `classlib`(src) / `xunit`(tests) + 참조 연결
4. **버그 시드**: 선택된 버그를 `Calculator.cs`에 **의도적 버그 상태**로 구현.
5. **테스트 생성**: happy-path는 통과(green), 각 버그의 실패 테스트는 **주석 또는 `[Fact(Skip=...)]`** 로 넣어 "학생이 해제→red→green" 흐름 유지.
6. **문서 생성**: `README`(분담표), `docs/분담표.md`, `docs/assignments/student-01..NN.md`.
7. **운영 파일**: `PULL_REQUEST_TEMPLATE.md`, `.github/workflows/ci.yml`.
8. **검증**: `dotnet test` → **현재 green**(버그 테스트는 비활성 상태)인지 확인.
9. (선택) `gh`로 버그별 Issue 생성.
10. **요약 출력**: 생성된 분담표 + 다음 단계(각 학생 fork 안내) 제시.

## 7. 워크드 예시 — `N=7, project=계산기, 혼합`

명령: **"7명에서 분담하여 만드는 계산기 샘플 만들어줘"**

### 생성될 분담표
| 학생 | 버그 id | 엣지 케이스 | 난이도 | 브랜치 | 카드 |
|---|---|---|---|---|---|
| 학생01 | B01 | 0으로 나누기 | 쉬움 | `fix/divide-by-zero` | `docs/assignments/student-01.md` |
| 학생02 | B03 | int 오버플로(곱셈) | 보통 | `fix/multiply-overflow` | `student-02.md` |
| 학생03 | B06 | 0^0 정의 | 어려움 | `fix/zero-pow-zero` | `student-03.md` |
| 학생04 | B02 | 음수 제곱근 | 쉬움 | `fix/negative-sqrt` | `student-04.md` |
| 학생05 | B04 | 반올림 정밀도 | 보통 | `fix/rounding-precision` | `student-05.md` |
| 학생06 | B11 | 부동소수 동등비교 | 어려움 | `fix/float-equality` | `student-06.md` |
| 학생07 | B08 | 퍼센트 base 0 | 쉬움 | `fix/percent-zero-base` | `student-07.md` |

(혼합 난이도 라운드로빈: 쉬움→보통→어려움 순환하며 7개 선택)

### 생성될 폴더
```
calculator-7/
├─ Calculator.slnx
├─ README.md                 # 위 분담표 포함
├─ src/Calculator/Calculator.cs        # B01,B03,B06,B02,B04,B11,B08 버그 시드
├─ tests/Calculator.Tests/CalculatorTests.cs
├─ docs/분담표.md
├─ docs/assignments/student-01.md ... student-07.md
└─ .github/{PULL_REQUEST_TEMPLATE.md, workflows/ci.yml}
```
→ `dotnet test` green 확인 후, 각 학생은 fork → 자기 카드의 브랜치에서 red→green→PR.

## 8. 확장 포인트
- **도메인 추가**: `날짜유틸`/`문자열파서` 버그 뱅크를 §2 형식으로 추가하면 동일 절차로 생성.
- **Classroom 연동**: 생성된 샘플을 Template 레포로 지정 → [C안](structure-C-github-classroom.md) autograding과 결합.
- **난이도 리포트**: 분담표에 난이도 합계를 넣어 학생 간 부하 균형 확인.
